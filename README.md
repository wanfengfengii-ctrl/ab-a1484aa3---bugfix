# 剧场升降幕配重挂装裁决

剧场更换升降幕前，机械师在浏览器中录入 **4~7 块幕布配重**（质量、可挂入的 **2~3 个导轨位置**、每个位置的安装代价）以及**卷扬轴限制**（总载荷上限、左右力矩闭区间），点击「裁决」后，页面联合确定**每块配重恰用一次的挂入位置**与**完整挂装次序**，保证挂装途中不失衡。

## 裁决规则

- **前缀约束**：挂装顺序的每一个前缀状态都必须同时满足 `已挂质量 ≤ 总载荷上限` 且 `合力矩 ∈ [力矩下端, 力矩上端]`（闭区间）。求解按挂装顺序逐步搜索并即时校验，**不会先选定最终位置再事后排序**。
- **力矩余量**：某前缀的力矩余量 = `min(力矩 − 下端, 上端 − 力矩)`；一套方案的力矩余量 = 其所有前缀力矩余量的最小值。
- **多套可行方案依次决胜**：
  1. 力矩余量最大者优先；
  2. 总安装代价最小者优先（代价按「块 × 采用位置」计，随位置选择而变化）；
  3. 按挂装顺序的 (块录入序号, 位置录入序号) 序列字典序最小者，保证结果稳定确定。
- **无可行方案**：页面指出最早无法继续挂装的步号（最深可行已选前缀的下一步），展示该已选前缀（多套并列时按上述优先级取最优者），并列出从该状态出发每个剩余 (配重, 位置) 选择触发的具体限制（总载荷超限 / 力矩低于下端 / 力矩高于上端）。
- **草稿即改即废**：任何录入修改立即撤销旧方案，需重新点击「裁决」。

## 页面功能

- 导轨位置（2~10 个）名称与力臂坐标（左负右正）编辑；
- 配重块（4~7 块）质量、可挂位置勾选（2~3 个）与各位置安装代价编辑，并显示位置录入序号；
- 卷扬轴总载荷上限与力矩闭区间录入；
- 裁决结果：可行时给出总代价、最小力矩余量、最终载荷/力矩摘要，支持**逐步查看**（上一步/下一步）每步的已挂质量、力矩、载荷/力矩余量、采用位置与未采用位置，并附完整挂装次序表；不可行时给出上述诊断；
- 录入校验：数量范围、正质量、非负代价、区间端点次序等，错误一次性全部列出。

## 本地开发

```bash
npm install
npm run dev        # 开发服务器（默认 5173 端口）
npm run test       # vitest 单元测试（裁决模块 + 录入校验）
npm run build      # 类型检查 + 生产构建（输出 dist/）
npm start          # 以生产静态服务器运行（默认 8080 端口，PORT 可配）
```

健康检查端点：`GET /healthz` → `{"status":"ok", ...}`。

## Docker 运行

```bash
# 构建并启动 Web（宿主机端口可通过 WEB_PORT 配置，默认 8080）
WEB_PORT=9000 docker compose up --build web

# 健康检查由镜像 HEALTHCHECK 与 compose healthcheck 双重定义，
# 就绪后访问 http://localhost:9000/
```

镜像为多阶段构建：`deps`（安装依赖）→ `build`（测试 + 构建）→ `web`（零依赖静态服务器 `server.mjs` + `HEALTHCHECK`）。

## 一次性 verify 服务

```bash
docker compose up --build --exit-code-from verify --abort-on-container-exit verify
echo $?   # 0 = 全部通过；非 0 = 失败
```

`verify` 服务在 `web` 健康检查后启动，依次完成：

1. **代码测试**：`vitest run`（裁决模块与前缀约束、决胜规则、不可行诊断、录入校验）；
2. **构建**：`tsc --noEmit && vite build`；
3. **冒烟**：`scripts/smoke.ts`
   - 裁决业务模块：确定性可行用例（位置/次序/代价/余量精确断言）与不可行用例（最深前缀与触发限制断言）；
   - 已启动页面：`GET http://web:8080/healthz` 返回 `status=ok`，首页返回含挂载点的 HTML；

随后自行退出，以上全部通过时退出码为 0，否则为 1。

## 项目结构

```
src/solver/          裁决业务模块（纯 TypeScript，与 UI 解耦）
  types.ts           场景 / 方案 / 步骤 / 不可行报告类型
  adjudicate.ts      联合求解：位置 × 次序 DFS + 前缀校验 + 分支限界 + 三级决胜
  validate.ts        录入约束校验
  *.test.ts          vitest 单元测试
src/draft.ts         草稿模型、默认录入、草稿 → 场景解析
src/components/      结果视图（逐步展示 / 不可行诊断）
src/App.tsx          录入界面与「草稿即改即废」逻辑
scripts/smoke.ts     verify 服务冒烟脚本
server.mjs           生产静态服务器（含 /healthz，零依赖）
Dockerfile           多阶段：deps / verify / build / web
docker-compose.yml   web（端口可配 + 健康检查）与一次性 verify 服务
```
